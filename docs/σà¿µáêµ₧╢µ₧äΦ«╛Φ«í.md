# DramaGenius 全栈后端架构设计

## 整体架构

```
用户浏览器
    │
    ▼
Nginx / 阿里云 API Gateway
    │
    ├── /api/auth/*       → 用户服务 (FastAPI)
    ├── /api/prophet/*    → Prophet 舆情服务 (FastAPI)
    ├── /api/soul/*       → Soul 角色服务 (FastAPI)
    ├── /api/arbiter/*    → Arbiter 决策服务 (FastAPI)
    ├── /api/workspace/*  → Workspace 创作服务 (FastAPI + WebSocket)
    │
    ├── PostgreSQL        → 用户/项目/剧本结构化数据
    ├── Redis             → 会话缓存 + 任务队列 + 限流
    ├── Elasticsearch     → 舆情数据全文检索 + 聚合分析
    ├── Lindorm/Milvus    → 角色记忆向量检索
    └── OSS               → 音频/文件/导出存储
```

## Task 2: 通义千问 LLM 统一服务层

核心封装 `app/services/llm_service.py`，所有模块通过这一层调用大模型：

```python
# 统一 LLM 服务 - 支持流式/非流式
class QwenService:
    # 模型选型策略:
    #   qwen-max       → 剧本续写、角色生成 (质量优先)
    #   qwen-plus      → 舆情分析、决策设计 (性价比)
    #   qwen-turbo     → 关键词提取、分类 (速度优先)

    async def chat(self, messages, model="qwen-max", stream=False)
    async def chat_stream(self, messages, model="qwen-max")  # SSE 流式
    async def function_call(self, messages, tools, model="qwen-plus")
```

**需要的 Prompt 模板**:
- `prophet_analyze`: 输入社媒原始数据 → 输出结构化舆情分析 (关键词/热度/趋势)
- `soul_character`: 输入创意概要 → 输出角色档案 (名字/性格/背景/台词风格)
- `soul_voice_desc`: 输入角色档案 → 输出声音描述 (用于 CosyVoice)
- `arbiter_decision`: 输入剧情大纲 → 输出决策点设计 + 变现策略
- `workspace_continue`: 输入已有剧本 + 上下文 → 流式续写剧本
- `workspace_outline`: 输入创意 → 输出 6 集大纲结构

## Task 3: Prophet 舆情系统

### 3.1 爬虫采集层

使用 Celery 定时任务调度爬虫，每个平台独立 Worker：

| 平台 | 采集方式 | 采集内容 | 频率 |
|------|---------|---------|------|
| 微博 | Playwright + 接口 | 热搜榜/话题/短剧相关帖子 | 每30分钟 |
| 抖音 | 接口抓取 | 热门短剧/评论/播放量 | 每1小时 |
| 小红书 | Playwright | 短剧笔记/话题/互动数据 | 每2小时 |
| B站 | 开放API | 短剧区视频/弹幕/评论 | 每1小时 |

采集数据存入 Elasticsearch，索引设计：
```json
{
  "platform": "weibo",
  "content": "原始文本...",
  "keywords": ["职场复仇", "短剧"],
  "sentiment": 0.82,
  "engagement": { "likes": 1200, "comments": 340 },
  "published_at": "2026-03-31T10:00:00Z"
}
```

### 3.2 分析 API

```
POST /api/prophet/analyze
  Body: { "query": "职场复仇短剧" }
  流程:
    1. ES 聚合查询 → 获取近7天相关帖子
    2. Qwen(qwen-plus) → 分析热度/趋势/情感
    3. 返回结构化结果: { keywords[], trends[], suggestions }
```

## Task 4: Soul 角色建模系统

### 4.1 角色生成

```
POST /api/soul/generate
  Body: { "project_id": "...", "concept": "职场女主复仇剧" }
  流程:
    1. Qwen(qwen-max) + soul_character prompt → 生成角色档案
    2. 存入 PostgreSQL (characters 表)
    3. 生成角色 embedding → 存入向量库 (用于后续记忆检索)
    4. 返回角色列表
```

### 4.2 语音克隆 (CosyVoice)

```
POST /api/soul/voice-preview
  Body: { "character_id": "...", "text": "试听台词" }
  流程:
    1. 读取角色声音描述
    2. 调用 CosyVoice API → 生成音频
    3. 上传 OSS → 返回音频 URL
```

### 4.3 角色记忆

使用向量数据库存储角色的记忆碎片，续写剧本时检索相关记忆注入 context：
```
POST /api/soul/memory/query
  Body: { "character_id": "...", "context": "当前场景描述" }
  → 返回 Top-K 相关记忆片段
```

## Task 5: Arbiter 决策引擎

```
POST /api/arbiter/design
  Body: { "project_id": "...", "outline": "剧情大纲..." }
  流程:
    1. Qwen(qwen-plus) + arbiter_decision prompt
    2. 输出: 决策点列表 + 分支选项 + 变现建议
    3. 存入 PostgreSQL (decisions 表)

POST /api/arbiter/simulate
  Body: { "decision_id": "...", "choice": "B" }
  → Qwen 模拟选择后的剧情走向预览
```

## Task 6: Workspace 创作工作台

### 6.1 方案生成 (整合 Prophet + Soul + Arbiter)

```
POST /api/workspace/generate-plan
  Body: { "concept": "职场女主复仇剧..." }
  流程 (并行调用):
    1. Prophet: 分析舆情 → 热点关键词
    2. Soul: 生成角色阵容
    3. Arbiter: 设计决策点
    4. Qwen(qwen-max): 融合以上结果 → 生成 6 集大纲
  返回: SSE 流式，前端逐步显示每个系统的结果
```

### 6.2 剧本续写 (核心交互 - 流式)

```
POST /api/workspace/continue
  Body: {
    "project_id": "...",
    "episode_id": 3,
    "context_scenes": [...已有场景],
    "characters": [...角色档案],
    "mood": "紧张",
    "instruction": ""  // 可选的用户指导
  }
  流程:
    1. 检索角色记忆 (向量库)
    2. 组装 context: 角色档案 + 已有剧本 + 记忆 + 氛围
    3. Qwen(qwen-max) 流式生成
    4. SSE 推送到前端 → 逐字显示
    5. 生成完成后存入 PostgreSQL
```

### 6.3 导出

```
POST /api/workspace/export
  Body: { "project_id": "...", "format": "docx|pdf|fountain" }
  → 生成文件上传 OSS → 返回下载链接
```

## Task 9: 部署方案 (阿里云)

```
                         ┌─ SLB ─┐
                         │       │
                    ┌────┴───┐  ┌┴────────┐
                    │ Nginx  │  │ CDN/OSS │
                    │ (前端) │  │ (静态)   │
                    └───┬────┘  └─────────┘
                        │
              ┌─────────┼──────────┐
              │         │          │
         ┌────┴───┐ ┌───┴────┐ ┌──┴─────┐
         │API Pod │ │API Pod │ │API Pod │  ← ACK (K8s)
         └────┬───┘ └───┬────┘ └──┬─────┘
              │         │         │
    ┌─────────┼─────────┼─────────┼──────────┐
    │         │         │         │          │
┌───┴──┐ ┌───┴──┐ ┌────┴──┐ ┌───┴────┐ ┌──┴──┐
│Postgres│ │Redis │ │  ES  │ │DashScope│ │ OSS │
│ RDS   │ │Tair  │ │云搜索 │ │(千问)   │ │     │
└───────┘ └──────┘ └───────┘ └────────┘ └─────┘
```

**阿里云服务映射**:
- 计算: ACK (容器服务) 或 ECS
- 数据库: RDS PostgreSQL
- 缓存: 云原生 Redis (Tair)
- 搜索: 阿里云 Elasticsearch
- 大模型: DashScope (百炼平台)
- 存储: OSS
- 网关: API Gateway + SLB
- 监控: ARMS + SLS
- 爬虫: FC (函数计算) 定时触发
